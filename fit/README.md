# Fitting scripts for `MODELS.fitted`

These scripts produce the tables embedded in `index.html` as `MODELS.fitted`. Each one
replaces a number that used to be set by hand. Raw data is not committed. Fetch it with
the commands below, then run the scripts with `python3 -I`. They need pandas, openpyxl
and pyreadr. Paths inside the scripts point at `/tmp/claude-0/...`; edit them to match
your machine.

`RESULT.json` whose `js_table` is pasted into `index.html` as the table named in the first column. The page's copy

and numbers; a few keys are renamed). The node probes load the page through `fit/harness.js`: `load(overrides, pagePath)` evaluates the model
half of a copy of `index.html` (by default `SNAP`, the page before the round) with exact source-text overrides, and
returns the model's API as `tests/load.js` exported it at that commit. Edit `SNAP` and each script's `HARNESS` (or the
equivalent constants) to match your machine.

**Tried and not usable:**
- Strategic interest and typical buyer pools by industry (`IND.strat`, `IND.buyers`). No source measures either for
  small businesses: vendor trackers see institutional deals only, and nobody counts the qualified buyers contacted per
  listing. `peer_checks.py` records what was found.
- A measured search-fund presence curve (`buyer_factors.py`): adopting it would move ENG_SHARE by 0.23-0.69 SE
  depending on how the curve is built, fits IBBA's offers by band worse than the hand-set window, and breaks the
  $2-5M calibration pin. Recorded in `MODELS.fitted.buyers.eta_check`.
- A latent-term EM for the SBA tail (the research round's `work/G-mechanics-tail/v2/run_termem.py`, not in the repo
  and not re-run by `sba_tail_factor.py`, which records it under `not_shipped.latent_term_EM`): AUC 0.966 on known
  terms, but it predicts 26% of
  charged-off notes long against 13% true, so the rewritten-term rule is used.
- Recurring-revenue medians for fitness and software (`peer_recurring_retention.py`): the Census product lines give a
  revenue-weighted share, not an establishment median (fitness: 0.65-0.98 under plausible spreads), and the software
  pool (0.89, SE 0.06) sits within one SE of the hand-set 0.85. Both stay judgment.
- Software growth (`peer_growth.py`): population-relevant sources disagree by up to 5.8 SE (SaaS Capital 25%, Empire
  Flippers -4%, Census forward 9%). Car-wash gross margin (`peer_gross_margin.py`): no source measures it on its
  definition.
- The listing panel's time-on-market. The median listing appears in one snapshot, and only
  164 sales were observed. (The curve's shape by size band is now fitted from IBBA's histograms instead.)
- The Main-Street size of the ask's effect on time to close. DealLedger's id-keyed broker panel has 31 sales in a
  six-week risk window: -0.14 (SE 0.55) on the sale hazard, no out-of-sample gain. `overpricing_time.py` takes the sign
  from online-marketplace analogs; the size (T_ELAST 0.10) is judgment.
- The thin-pool factor's shape. IBBA's offer histograms are of closed deals, so listings with no offer are never
  seen; a negative binomial fits the counts better but its chance of no offer is an extrapolation (under $500K it
  gives a typical listing a 0.50 chance of any offer, below Pepperdine's 0.61 close rate). Only the scale
  (`ENG_SHARE`) is used; the Poisson shape and the cap stay judgment.
- Online-business sales for the weights of recurring revenue and growth (`quality_weights_v2.py`). Empire Flippers and
  Flippa fix the direction of growth on sale prices (mostly a discount on declining businesses), not its weight; for
  recurring revenue only the asking-price premium is significant. Neither says anything about owner dependence or
  management depth (EF owners work a median 3 h/week). All seven unpriced dimensions keep weight 1.
- Anchoring of sale price on ask (alpha, A_max). Sale-to-ask data fix (1 - alpha) * s, not alpha;
  `anchoring_realization.py` calibrates s and leaves alpha as judgment.
